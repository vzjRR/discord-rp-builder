# خطة مشروع: مطعم مثلجات لـ GTA V / FiveM

> وثيقة الخطة الرسمية للمورد `enclave_icecream`.
> كُتبت بعد بحث في معايير بناء موارد FiveM الحديثة (2025–2026) ومراجعة الأنماط المتبعة في
> موارد الوظائف/المطاعم المنشورة.

---

## 0) ملخص تنفيذي

مورد FiveM كامل لمطعم/محل مثلجات قابل للعب كـ **وظيفة (Job)** داخل السيرفر:
الموظف يسجّل دوام، يستلم مواد خام، يصنع المثلجات على محطات عمل حقيقية،
يستقبل طلبات زبائن (NPC أو لاعبين)، يحصّل الفلوس عبر كاشير، والأرباح تدخل
**حساب الشركة**، والمدير يديرها من **منيو البوس**. مع نظام توصيل، وتوريد مواد،
ورواتب، وإحصائيات، ولوقات ديسكورد.

الهدف: مورد **جاهز للإنتاج** — لا سكربت تجريبي — يشتغل على أشهر الفريمويركات
بدون تعديل كود، فقط تعديل ملف إعدادات.

## 1) نتائج البحث — الأسس التي بُني عليها المشروع

### 1.1 المانيفست `fxmanifest.lua`
| القاعدة | القرار في مشروعنا |
|---|---|
| `fx_version` الأحدث والأكثر أمانًا هو `cerulean` | ✅ نستخدم `cerulean` |
| `game 'gta5'` (لا نستخدم `common` لأنها تفقد النيتيفات) | ✅ |
| `lua54 'yes'` مطلوب لكل الفريمويركات الحديثة (Qbox / QBCore الحديث / Ox) | ✅ |
| الاعتماديات الصلبة تُعلن في `dependencies` والناعمة عبر `@resource/file.lua` | ✅ `@ox_lib/init.lua` كـ shared، و`dependencies` فيها ox_lib فقط |
| لا تضع أسرار السيرفر (توكنات/ويبهوك/باسوردات) في `shared_scripts` | ✅ الويبهوك في `server/` + `Config.Server` منفصل |
| الخطأ الأشيع: نسخ مانيفست ضخم من مورد ثانٍ وترك اعتماديات لا تحتاجها | ✅ المانيفست مكتوب من الصفر |

### 1.2 معمارية موارد الوظائف الناجحة (مقارنة موارد المطاعم المنشورة)
الموارد التجارية الناجحة (Burgershot، KOI، Restaurant & Chef، qb-business-food) تشترك في:

1. **جسر فريمويرك (bridge)**: ملف واحد يُحمّل تلقائيًا حسب الموجود على السيرفر،
   والباقي من الكود لا يعرف أي فريمويرك يشتغل. → **نطبّقها**.
2. **كل شيء في `config`**: المواقع، الوصفات، الأسعار، الرواتب — بلا لمس الكود.
   → **نطبّقها** مع تقسيم الكونفق لأربعة ملفات بدل ملف عملاق.
3. **محطات عمل مستقلة** (ماكينة، طاولة تحضير، خلاط، فريزر) كل وحدة لها وصفاتها.
   → **نطبّقها** عبر نظام `stations` معرّف بالبيانات.
4. **تصنيع بمكونات حقيقية** (مو ضغطة زر تعطيك منتج) + شريط تقدم + أنيميشن.
   → **نطبّقها** مع تحقق سيرفري كامل.
5. **دورة اقتصادية مغلقة**: توريد ← تصنيع ← بيع ← حساب الشركة ← رواتب.
   → **نطبّقها** كاملة (أغلب السكربتات المجانية تكسر الحلقة عند البيع).
6. **منيو بوس**: سحب/إيداع، توظيف/فصل، ترقية، إحصائيات.
   → **نطبّقها**.

### 1.3 مكتبات النظام البيئي المعتمدة
| المكتبة | الاستخدام عندنا | السبب |
|---|---|---|
| `ox_lib` | القوائم `registerContext/showContext`، `progressBar/progressCircle`، `TextUI`، `notify`، `callback`، `points`، `skillCheck` | المعيار الفعلي في 2026، وكل الفريمويركات الحديثة تعتمد عليها |
| `ox_target` | `addBoxZone` / `addSphereZone` / `addModel` للتفاعل مع المحطات | الأفضل أداءً وأنظف API؛ مع بديل `qb-target` |
| `ox_inventory` | `AddItem` / `RemoveItem` / `CanCarryItem` / `Search` / `RegisterStash` | يدعم الميتاداتا والتلف (degrade) — مهم للمثلجات! |
| `oxmysql` | حفظ حساب الشركة والإحصائيات والطلبات | المعيار |

### 1.4 نقاط تصميمية خاصة بمحل مثلجات (ما تنطبق على مطعم عادي)
- **الذوبان**: المثلجات تذوب مع الوقت → نستخدم `degrade` في `ox_inventory` +
  ميتاداتا `freshness`، وتنخفض قيمة البيع كلما ذاب المنتج.
- **الفريزر**: ستاش وظيفي يحافظ على المنتج (منطقيًا) ويُستخدم كمخزن الفرع.
- **المواسم / الطقس**: مبيعات أعلى وقت النهار والجو الحار → مضاعف طلبات NPC.
- **عربة الآيس كريم (Ice Cream Truck)**: مركبة `taco`/`ice cream van` للبيع المتنقل
  في نقاط ساخنة على الخريطة — ميزة مميزة لمحل مثلجات تحديدًا.

### 1.5 الأمان (server-authoritative)
كل موارد الوظائف المخترقة تشترك في نفس الثغرة: العميل يقول «صنعت منتج» والسيرفر يصدّق.
قواعدنا:
- ❌ ما في `RegisterNetEvent` يعطي فلوس أو عناصر بناءً على وسائط من العميل بلا تحقق.
- ✅ كل حدث سيرفري يتحقق من: الوظيفة، الرتبة، الدوام، **المسافة** لإحداثيات المحطة،
  توفّر المكونات فعليًا، و**حد معدّل (rate limit)** لكل لاعب.
- ✅ المعرّفات (recipe id / station id) تُتحقق مقابل الكونفق المشترك، ما تُستخدم كما جاءت.

## 2) معمارية المورد

```
fivem/enclave_icecream/
├── fxmanifest.lua              # cerulean + lua54 + ox_lib
├── config/
│   ├── config.lua              # الإعدادات العامة (الوظيفة، الاقتصاد، الرواتب، المفاتيح)
│   ├── locations.lua           # الفروع، المحطات، البلبس، الفريزرات، نقاط التوصيل
│   ├── recipes.lua             # الوصفات لكل محطة (المكونات، الوقت، الأنيميشن)
│   └── items.lua               # تعريفات عناصر ox_inventory جاهزة للنسخ
├── locales/{ar,en}.json        # الترجمة (العربية هي الافتراضية)
├── bridge/{client,server}.lua  # جسر الفريمويرك + جسر الحقيبة + جسر التارجت
├── client/
│   ├── main.lua                # التهيئة، البلبس، الدوام، الحالة
│   ├── targets.lua             # تسجيل مناطق التفاعل
│   ├── craft.lua               # واجهة التصنيع + شريط التقدم + الأنيميشن
│   ├── register.lua            # الكاشير + الفوترة + طلبات الزبائن
│   ├── orders.lua              # زبائن NPC وطلباتهم
│   ├── supply.lua              # جولة التوريد
│   ├── truck.lua               # عربة المثلجات المتنقلة
│   └── boss.lua                # منيو البوس (واجهة)
├── server/
│   ├── main.lua                # التهيئة، الحالة، الأدوات المشتركة
│   ├── craft.lua               # تحقق وتنفيذ التصنيع
│   ├── register.lua            # الفوترة والدفع
│   ├── orders.lua              # توليد الطلبات وتسليمها
│   ├── supply.lua              # شراء المواد الخام
│   ├── truck.lua               # البيع المتنقل
│   ├── society.lua             # حساب الشركة + الرواتب + منيو البوس
│   ├── db.lua                  # oxmysql
│   └── logs.lua                # ويبهوك ديسكورد
├── sql/install.sql
└── docs/{INSTALL,CONFIG,API,TROUBLESHOOTING}.md
```

**قاعدة التحميل**: `config/*` و `bridge/*` shared → ثم `client/*` أو `server/*`.
كل ملف يعرّف موديولًا في جدول `IC` العام داخل المورد (بيئة Lua معزولة لكل مورد، فلا تلوث).

## 3) الميزات — القائمة النهائية

### أ) الوظيفة والدوام
- وظيفة `icecream` بخمس رتب: متدرب / موزّع / صانع / مساعد مدير / مالك.
- نقطة تسجيل دوام (`ox_target` + بلب) مع TextUI.
- خارج الدوام: لا تصنيع ولا فوترة ولا وصول للفريزر.

### ب) المحطات والتصنيع
| المحطة | المنتج |
|---|---|
| ماكينة السوفت سيرف | كرات المثلجات الأساسية (فانيليا، شوكولا، فراولة، مانجو…) |
| طاولة التحضير | كون/وافل/كوب + إضافة التوبينغز → منتج نهائي |
| الخلاط | ميلك شيك وسموذي |
| الفرن الصغير | كون وافل طازج + براوني |
| الفريزر | ستاش الفرع (وظيفي، مشترك) |
- كل وصفة: مكونات + وقت + أنيميشن + رتبة مطلوبة + احتمالية `skillCheck`.
- منع التصنيع إذا الحقيبة ما تتحمل (`CanCarryItem`).

### ج) البيع
1. **زبائن NPC**: يظهر زبون على الكاونتر بطلب محدد ووقت صلاحية → التسليم
   يعطي سعر البيع (نسبة للشركة + نسبة بقشيش للموظف).
2. **بيع للاعبين**: كاشير يفوتر لاعب قريب بمبلغ من قائمة الأسعار، والدفع
   يذهب لحساب الشركة.
3. **عربة المثلجات**: بيع متنقل في نقاط ساخنة، أسعار أعلى، لكن مخزون محدود.

### د) التوريد
- نقطة مورّد جملة: شراء حليب/سكر/فواكه/أكواب بسعر جملة من حساب الشركة.
- خيار «جولة توريد» بشاحنة: تحميل من مستودع وتوصيل للفرع = ربح إضافي.

### هـ) حساب الشركة ومنيو البوس
- رصيد شركة مستقل محفوظ في قاعدة البيانات.
- إيداع/سحب (مع لوق ديسكورد لكل عملية).
- توظيف/فصل/ترقية الموظفين.
- إحصائيات: مبيعات اليوم/الأسبوع، أفضل موظف، أكثر منتج مبيعًا.
- رواتب دورية تُخصم من حساب الشركة (اختياري، قابل للإيقاف).

### و) البنية التحتية
- لغتان (ar افتراضي / en).
- لوقات Discord Webhook لكل حدث مالي أو إداري — يتكامل مع فلسفة هذا المستودع.
- تخزين `oxmysql` مع migration تلقائي عند أول تشغيل.
- Exports عامة ليستفيد منها بقية موارد السيرفر.
