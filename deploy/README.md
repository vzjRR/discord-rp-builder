# النشر على Oracle Cloud

## ابدأ من هنا

**[`all-in-one/`](./all-in-one/) — كل شيء على خادم واحد. هذا الموصى به.**
تلصق ملف cloud-init واحدًا فتُركَّب الخدمات الثلاث.

الشريحة المجانية الواحدة تسعها بفائض كبير، والمنصة وبوت Enclave يتشاركان
قاعدة أحداث السيرفر أصلًا فبقاؤهما معًا أبسط وأكمل.

والجمع في خادم لا يعني الدمج في خدمة: لكل واحدة ملف أسرار مستقل ووحدة
تشغيل مستقلة، تُشغَّل وتُوقَف وتُحدَّث على حدة، وسقوط إحداها لا يُسقط
غيرها.

## نشرات منفردة

إن أردت خدمة على خادمها الخاص، فلكل واحدة `cloud-init.yaml` مستقل:

| المجلد | ما ينشره | السيرفر |
|---|---|---|
| [`enclave-panel/`](./enclave-panel/) | منصة الإدارة | Enclave |
| [`enclave-bot/`](./enclave-bot/) | بوت الترحيب وتتبّع الحركة | Enclave |
| [`lspd-bot/`](./lspd-bot/) | بوت السيرفر (كل شيء) | LSPD |

`common/install-base.sh` هو الأساس المشترك (الحزم، Node، مستخدم التشغيل،
الكود، الجدار الناري). و`install.sh` في كل مجلد يحوي خطوات تلك الخدمة
وحدها — يستدعيه `setup.sh` للنشر المنفرد، ويستدعيه `all-in-one` للمجمّع،
فلا يتكرر التعريف في موضعين.

> `logs-bot/` في المستودع لا نشرة له: لم يكن يعمل على الاستضافة السابقة.
> لكلّ سيرفر بوت واحد. إن أردته لاحقًا فنشرته تُبنى على المنوال نفسه.

## كيف تنشر خدمة

من لوحة Oracle Cloud: **Compute ← Instances ← Create instance**

| الخيار | القيمة |
|---|---|
| Image | Ubuntu 24.04 |
| Shape | `VM.Standard.A1.Flex` — ٢ معالج و١٢ غيغابايت |

هذه الشريحة ضمن «Always Free» دائمًا. المتاح مجانًا ٤ معالجات و٢٤
غيغابايت موزّعة كما تشاء بين الخوادم، وما فوقها يُحاسَب. ولا تختر
`E2.1.Micro` ذات الغيغابايت الواحد — تضيق بتوليد الصور.

ثم **Advanced options ← Management ← Paste cloud-init script**، والصق
محتوى `cloud-init.yaml` من مجلد الخدمة التي تنشرها.

احفظ مفتاح SSH الذي تعرضه الصفحة. لن تحتاجه غالبًا، لكن فقدانه يعني
فقدان الطريق الوحيد إلى الخادم إن تعطّل شيء.

يهيّئ الخادم نفسه خلال خمس إلى عشر دقائق، ثم تُكمل من **Cloud Shell**
(أيقونة الطرفية في لوحة Oracle — تعمل داخل المتصفح، ولا تحتاج برنامجًا
على الآيباد):

```bash
ssh ubuntu@<عنوان-الخادم>
sudo -i
nano /etc/enclave/<اسم-الخدمة>.env    # املأ الأسرار
systemctl enable --now <اسم-الخدمة>
journalctl -u <اسم-الخدمة> -f
```

التفاصيل الخاصة بكل خدمة في `README.md` داخل مجلدها.

## إن فرّقتها على خوادم

**المنصة وبوت Enclave يبقيان معًا** — يتشاركان `/data/server-events.db`:
البوت يكتبه والمنصة تقرأه. لو فُصلا عملت المنصة كاملةً عدا «آخر
المغادرين» و«الأكثر تفاعلًا» في صفحة حالة السيرفر، فتلك بيانات لا يملكها
إلا البوت.

**بوت LSPD حيث شئت** — لا يشارك أحدًا شيئًا.

## الدخول عبر نفق Cloudflare

المنصة وحدها تحتاج وصولًا من الخارج. تصلها عبر نفق يفتحه الخادم اتصالًا
**صادرًا** إلى Cloudflare، فلا منفذ وارد ولا مستمع عام.

وأثر ذلك مباشر: **لا يوجد رابط استضافة خام يمكن أن يتسرّب أصلًا** — ولا
عنوان يُكتشف، ولا شهادة تُدار على الأصل.

من لوحة Cloudflare: **Zero Trust ← Networks ← Tunnels ← Create a tunnel**

1. اختر **Cloudflared**، وسمِّ النفق `enclave`.
2. انسخ رمز التثبيت (سطر طويل يبدأ بـ `eyJ...`).
3. أضف Public hostname:
   - **Subdomain** `enclave-admin` — **Domain** `tsh87.com`
   - **Service** `HTTP` ← `localhost:3000`
4. على خادم المنصة: `cloudflared service install <الرمز>`

Cloudflare ينشئ سجلّ الـ DNS تلقائيًا. بعدها احذف أي سجلّ قديم لهذا
الاسم، والـ Worker السابق — لم تعد له وظيفة.

**لا تحذف شيئًا من الاستضافة القديمة قبل اكتمال هذه القائمة:**

- [ ] `https://enclave-admin.tsh87.com` تفتح صفحة الدخول

- [ ] «حالة السيرفر» تعرض الأعضاء
- [ ] عضو جديد يدخل Enclave فتصله صورة ترحيب
- [ ] عضو جديد يدخل LSPD فتصله صورة ترحيب

**عند اكتمالها كلها فقط** احذف مشاريع الاستضافة القديمة.

## التشغيل اليومي

**تحديث الكود:**

```bash
cd /opt/enclave && git pull
systemctl restart <اسم-الخدمة>
```

**نسخة احتياطية** — من المنصة: «إدارة الحسابات» ← تنزيل النسخة
الاحتياطية. اجعلها عادة شهرية واحفظها خارج الخادم؛ فنسخة تعيش على
الجهاز الذي تحميه ليست نسخة احتياطية.

## خطأ «Incorrectly formatted request» عند الإنشاء

رسالة عامة من أوراكل تعني أن الطلب رُفض قبل أن يُنشأ شيء — لم يُقتطع من
حصتك المجانية، وإعادة المحاولة آمنة.

جرّبها بالترتيب:

**١) ملف cloud-init.** ملفات هذا المجلد بالإنجليزية عمدًا: الكونسول
يُرمّز هذا الحقل بـ base64، ومُتحقِّقه يرفض المحارف غير اللاتينية. فإن
لصقت نصًّا عربيًا أو رموزًا تعبيرية في تلك الخانة فسيفشل الطلب. الصق
الملف كما هو دون تعديل.

**٢) اعزل السبب.** أنشئ الخادم **بدون** لصق cloud-init إطلاقًا. فإن نجح
فالمشكلة في محتوى الخانة؛ وإن فشل فهي في إعداد آخر — والتهيئة يمكن
تشغيلها يدويًا بعد الإنشاء:

```bash
sudo bash -c "$(curl -fsSL https://raw.githubusercontent.com/vzjRR/discord-rp-builder/master/deploy/all-in-one/setup.sh)"
```

**٣) شريحة A1.Flex.** حدّد عدد المعالجات والذاكرة صراحةً (٢ و١٢
غيغابايت). تركها فارغة أو وضع تركيبة غير مسموحة يُرفض.

**٤) الشبكة.** إن لم تكن لديك شبكة سحابية (VCN) فاختر «Create new virtual
cloud network»، وتأكد من تفعيل **Assign a public IPv4 address**.

**٥) مفتاح SSH.** لا بد من مفتاح: إمّا توليده من الصفحة، أو لصق مفتاح
عام صالح. ولصق مفتاح **خاص** أو نصّ ناقص يُرفض الطلب.

**٦) نفدت السعة.** لو ظهرت «Out of host capacity» فهي رسالة أخرى تعني أن
منطقتك مزدحمة — جرّب نطاق توفّر (Availability Domain) آخر أو أعد المحاولة
لاحقًا.

## إن تعطّل شيء

| العرَض | الفحص |
|---|---|
| التهيئة لم تكتمل | `cat /var/log/bootstrap-<الخدمة>.log` |
| خدمة لا تعمل | `journalctl -u <الخدمة> -n 50 --no-pager` |
| الدومين لا يفتح | `systemctl status cloudflared` ثم راجع Public hostname |
| المنصة ترد ٤٠٤ على كل شيء | `CLOUDFLARE_SECRET` لا يطابق قاعدة Cloudflare — أو عطّل `REQUIRE_CLOUDFLARE` مؤقتًا |
| صورة الترحيب بمربعات فارغة | `FONTCONFIG_PATH` لا يشير إلى مجلد الخطوط |
| البوت يرحّب في السيرفر الخطأ | خلط بين ملفَّي الأسرار — لكل بوت ملفه |
