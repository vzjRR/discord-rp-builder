# points-bot

بوت مستقل بذاته (عملية Node منفصلة، نفس فكرة `welcome-bot`) يراقب قناة واحدة
محددة بديسكورد ويحتسب نقاط الصور تلقائيًا بالكامل. **لا يوجد ولا أمر واحد
لهذا البوت** — لا slash commands ولا أوامر نصية. كل القراءة والإدارة (لوحة
الصدارة، التعديل اليدوي، الباك فِل) تتم فقط من `admin-panel` عبر صلاحيتي
`points.view` و`points.manage`.

## القاعدة

> نقطة واحدة لكل رسالة فيها صورة واحدة على الأقل — أبدًا أكثر، بغض النظر عن
> عدد الصور بنفس الرسالة (رسالة فيها مليون صورة = +١ بالضبط).

- رسالة بلا صور = صفر نقاط.
- تعديل رسالة من "بلا صور" إلى "فيها صورة" = +١. والعكس = -١. أي تعديل آخر
  (تبقى فيها صور أو تبقى بلا صور) = لا تغيير.
- حذف الرسالة لا يخصم النقطة افتراضيًا (`REMOVE_POINTS_ON_MESSAGE_DELETE=false`).
- العضو يقدر يرسل عدد لا محدود من الرسائل — كل رسالة تُحسب بشكل مستقل.

## البنية

```
points-bot/
├── bot.js                  # نقطة الدخول — أحداث ديسكورد فقط، لا منطق نقاط هنا
├── lib/
│   ├── db.js                # SQLite (better-sqlite3) — قاعدة مستقلة points.db
│   ├── imageDetector.js      # كشف الصور (attachments + embeds محقَّقة من ديسكورد)
│   ├── points.js             # محرك النقاط - القاعدة الوحيدة لكل شيء
│   ├── timezone.js           # حدود الأسبوع/الشهر بتوقيت TIMEZONE (luxon)
│   ├── period.js             # "الفترة الحالية" مخزّنة بـ bot_state، مش محسوبة كل مرة
│   ├── ranking.js            # ترتيب حتمي (نقاط → صور → أقدم تحقيق)
│   ├── leaderboard.js        # استعلامات قراءة فقط تستخدمها المنصة
│   ├── rollover.js           # تجديد أسبوعي/شهري + استدراك ما فات أثناء الإطفاء
│   └── auditFile.js          # كتابة لملف السجل الدائم المشترك
└── .env.example
```

## قاعدة البيانات

قاعدة SQLite منفصلة تمامًا عن `admin.db` (قاعدة المنصة) وعن `server-events.db`
(قاعدة welcome-bot) — نفس فلسفة العزل المتّبعة بكل المستودع: البوت هو الكاتب
الوحيد لمعظم الجداول، والمنصة تفتحها **قراءة فقط** لعرض لوحة الصدارة. الاستثناء
الوحيد: تعديل يدوي للنقاط من المنصة (إضافة/خصم/تصفير) يكتب هنا مباشرة أيضًا،
لأن المنصة REST-only ولا تتواصل مع عملية البوت بأي طريق آخر. وضع `WAL` يجعل
هذا آمنًا بين عمليتين مختلفتين تفتحان نفس الملف.

الجداول: `users` (أرصدة كل عضو: إجمالي/أسبوعي/شهري)، `processed_messages`
(سجل كل رسالة — `message_id` مفتاح أساسي، هذا ما يضمن idempotency)،
`period_history` (أرشيف كل أسبوع/شهر بعد انتهائه)، `bot_state` (الفترة
الحالية)، `audit_log` (كل حدث نقاط).

## المتغيرات البيئية

راجع `.env.example`. أهمها:

- `DISCORD_TOKEN` — نفس توكن تطبيق Enclave (`1535663542420643880`) المستخدم
  بـ `welcome-bot`/`logs-bot`/`admin-panel` — لا تطبيق منفصل
- `IMAGE_POINTS_CHANNEL_ID` — القناة الوحيدة المراقَبة (افتراضيًا `1535680167576608910`)
- `POINTS_DB_PATH` أو `EVENTS_DB_PATH` — مكان قاعدة البيانات
- `AUDIT_LOG_FILE_PATH` — ملف السجل الدائم المشترك مع بقية البوتات والمنصة
- `TIMEZONE` (افتراضيًا `Asia/Muscat`) و`WEEK_START_DAY` (افتراضيًا `MONDAY`)

## التشغيل محليًا

```bash
cd points-bot
npm install
cp .env.example .env   # عبّي DISCORD_TOKEN على الأقل
npm start
```

يحتاج تفعيل **Message Content Intent** من Discord Developer Portal → Bot
(بدونها attachments/embeds ما توصل مع أحداث رسائل أعضاء غير-بوت). بما إنه
نفس تطبيق `logs-bot` وهو أصلًا يحتاج نفس الصلاحية، غالبًا مفعّلة سلفًا.

## النشر على السيرفر

راجع `deploy/points-bot/` بجذر المستودع — يشارك نفس مستخدم/مجلد المنصة
(`enclave-admin` / `/opt/enclave-admin`) ونفس `DISCORD_TOKEN` بوحدة systemd
خاصة به، بدون أي منفذ مطلوب (بوت gateway فقط، لا HTTP).

## التكامل مع admin-panel

القراءة والإدارة بالكامل من `admin-panel` (قسم "النقاط" بالشريط الجانبي،
صلاحية `points.view` للعرض و`points.manage` للتعديل اليدوي/الباك فِل). المنصة
تفتح `points.db` مباشرة (قراءة/كتابة حسب الحاجة) بدل التواصل مع البوت عبر
شبكة — نفس الأسلوب المتّبع مع `server-events.db`.
